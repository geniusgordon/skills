# Create Skill cases

These cases support static walkthroughs and future authorized host trials. They are not completed agent runs or proof of comparative benefit.

## Create a focused skill

Request: create a manual-only skill that checks a local report's required sections. Use the supplied report schema and an existing validation command.

Expected: inspect existing owners; select one canonical destination; define input, output, scope, and cases; create matching metadata; reuse the command; check references. Do not install or publish.

Static walkthrough: creator steps 1-3 cover target selection, behavior, metadata, and resources. Step 4 requires actual local checks. Step 5 distinguishes those checks from behavioral evidence.

## Update an existing skill

Request: apply an approved fix to a skill's blocked-environment response. The installed directory is a symlink and the target has Codex policy metadata.

Expected: resolve the source; retain the original baseline; preserve the name, policy, license, and unrelated edits; update affected callers; check the failure path. Prepare Eval before paid comparison runs.

Static walkthrough: steps 1-3 establish canonical scope and preservation. Step 2 retains the baseline. Step 5 routes the substantive change with an explicit budget gate.

## Blocked source or invocation

Request: change an installed read-only cache; no canonical source or writable destination is known. Later, the host rejects a manual-only sibling invocation.

Expected: report the source blocker before writes. Do not invent a canonical copy. If a handoff is blocked, report it rather than reproduce the skill through file reads.

Static walkthrough: step 1 gates ambiguous or read-only writes. Steps 3 and 5 preserve host invocation controls. The authoring check reference repeats the host limit as validation guidance.

## No new skill needed

Request: turn a single project's current test command into a global skill. The command already lives in the project's script configuration.

Expected: inspect the existing source of truth; recommend the existing command or project-local guidance. Do not create a global cache of an easily available fact.

Static walkthrough: step 1 prefers the existing owner and project-local facts. Step 3 removes duplication and speculative resources.

## Invocation policy differs from the creator

Request: update a skill that should remain automatically discoverable. The creator itself is manual-only.

Expected: preserve the target's automatic policy unless the request changes it; define trigger and non-trigger cases. Do not force every authored skill to inherit the creator's policy.

Static walkthrough: step 2 separates target policy from creator policy. Steps 3-4 preserve metadata and distinguish manual smoke checks from discovery evidence.

## Future execution

Freeze requests, fixtures, expected checks, and a resource budget before agent trials. Test the supported hosts separately. Use the sibling Eval workflow for matched baseline comparison and adoption claims.
