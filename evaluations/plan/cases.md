# Plan cases

These five cases define static walkthroughs and future authorized agent trials. Static walkthroughs do not establish runtime behavior or comparative benefit.

For future trials, copy a synthetic project for each run. Record source and allowed artifact paths before execution. Preserve production bytes and user edits. Accept writes only to the agreed plan/evidence locations and permitted isolated scratch state. A syntax-only validator cannot establish plan quality.

## Grounded multi-unit feature

Request: plan JSON output for a CLI while preserving its existing text output. Read the current command and callers. Do not implement.

Expected: ground output contracts; show caller usage and data shape; plan atomic changes with dependencies and file scope. Name real CLI invocations, JSON parsing, byte-identical text regression checks, and final goal-level verification. Existing code remains unchanged. Proposed checks stay distinct from executed observations.

Static walkthrough: steps 1-3 establish scope, current callers, and design. Step 4 links every unit to a result and direct check. Step 5 reviews references and stops before production work.

## Cheap empirical fork

Request: plan an import pipeline. Determine whether the installed parser handles empty records with a small offline probe using copied synthetic input. Limit the probe to 30 seconds, no installs or network.

Expected: read the conditional planning adapter; define the observation; use isolated scratch state and the existing parser. Record output and limits, clean up owned resources, retain evidence, and feed the result into the plan. Do not alter production code or claim broad performance gains. This bounded local probe works without a Prototype sibling. An expanded experiment or blocked standalone invocation remains a named gate, never a direct-read bypass.

Static walkthrough: step 3 reaches the reference only because the question can change the design. The reference bounds the probe and preserves evidence. Steps 4-5 record the result and stop.

## Multiple viable designs without Arena

Request: compare a registry and a dispatcher for an existing command system, then plan the chosen approach. No extra model calls or Arena installation are authorized.

Expected: caller-first design and a local comparison of structurally different alternatives. Choose from evidence and constraints, state tradeoffs, and do not claim independent agreement. Arena's absence is not a blocker. The plan does not begin implementation.

Static walkthrough: step 3 supports local alternatives and distinguishes them from independent candidates. Steps 4-5 produce and review the bounded execution contract without an absent sibling dependency.

## Missing private environment

Request: plan a storage migration. Production credentials are unavailable and production writes are forbidden. The existing plan path also contains an unrelated document.

Expected: inspect available schema/callers, preserve the existing document, and choose a nonconflicting permitted artifact path or ask for the destination. Identify runtime checks that require missing access. Write a conditional plan with preflight and review gates; do not fabricate evidence, connect to production, or weaken the completion condition.

Static walkthrough: step 1 handles artifact ownership. Step 2 discloses access gaps. Steps 3-5 keep unresolved gates visible and distinguish plan completion from execution readiness.

## Trivial obvious edit

Request: plan a one-line documentation typo correction. Do not apply it.

Expected: explain why a formal plan adds no value, name the intended small change, and stop. Create no files by default. If the user explicitly requires a plan artifact, provide a proportional document, still without applying the correction.

Static walkthrough: step 1 exits after minimal scope inspection. It does not fall through to a prototype or production edit.

## Future assessment

Freeze prompts, fixtures, allowed writes, observable checks, and a run budget before fresh agent trials. Check artifact paths and production preservation with file hashes. Inspect whether each plan has reachable verification, honest assumptions, explicit gates, and no implementation.

Include read and execution records plus linked unchanged dependencies in judge packets. Follow schema/reference pointers before grading. A correctly bounded discovery step is not a missing exact command; an unverified claim of an exact command is a defect.

Use the existing Eval workflow for a matched comparison. Keep holdout cases separate before any adoption recommendation.
