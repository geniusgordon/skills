# Task checkpoint contract

Use these five sections for one selected task. Fill them with observed facts; mark unknown, unavailable, or not applicable instead of inventing data. Do not copy this guidance as unfinished placeholders.

## 1. Goal and authority

Record task identity, user goal, scope/non-goals, optional plan path, recorded approvals, and current permission limits. Historical approvals remain evidence, not a new grant to the next session.

Use a local note appropriate to the data's sensitivity. Avoid secrets and raw private transcripts. Redact values without losing the action's meaning. Do not publish the note without permission.

## 2. Progress and decisions

Record completed units, the active unit, pending units and dependencies, accepted/rejected decisions, and rationale or decision-trail pointers. Use concise facts, not source dumps or a rewritten plan.

Separate a claimed completion from its evidence. Mark unfinished atomic steps and whether any writer can still change the artifacts.

## 3. Operational snapshot

Record observation time, project/workspace identity, repository root, branch, revision, dirty files, relevant task handles, process identities, owned resources, and what remains live.

For non-Git tasks, describe the actual artifact identity. Record unavailable host state. A PID or old task status alone establishes no current process ownership.

State whether this is a live snapshot or a quiescent boundary. The checkpoint does not preserve dirty code, memory, open transactions, or processes. Identify ephemeral paths and restart risks.

## 4. Evidence and blockers

For relevant checks, record the artifact/revision, executed command or interaction, expected/observed result, and evidence path. Separate planned commands from checks already run.

Mark missing, stale, inaccessible, or incomplete evidence and unresolved blockers. Link external records only when authorized. A missing artifact cannot support a completed verdict.

## 5. Next action and recovery

Name one next bounded action, its prerequisites and gates, and the minimum state checks needed before it. Record conflicts, sensitive operations, and ownership issues that require resolution.

On resume, compare the note with current artifacts. Recheck changed or unsupported claims without repeating the whole investigation. If continuation is not authorized, provide the resume point and stop.
