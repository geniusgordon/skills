# Reflection proposals

## Evidence scope

- Session or visible conversation reviewed:
- Actual skill loads and artifacts:
- Missing records and uncertainty:
- Review method: single agent / authorized independent reviewers.

## Accepted: pending approval

For each item:

1. Lesson: the condition and future action.
2. Evidence: exact turn, quote, command result, or artifact path and line.
3. Diagnosis: body gap / placement / discovery / manual routing / project convention.
4. Destination: canonical file and section; note any symlink resolution.
5. Proposed change: exact replacement or small diff.

Then state the expected benefit, affected workflows, relevant check, and confidence. A single incident supports a scoped hypothesis, not proven general benefit.

## Rejected

For each item, name the lesson and reason: insufficient evidence, already covered, execution failure, overly specific, or no decision change. Do not hide a meaningful unresolved issue as a rejection.

## Backlog

For each item, give the evidence, suggested structural mechanism, and scope. State that nothing was filed externally unless the user authorized it.

## Approval

Ask which proposals to apply. Wait before edits. Keep approved scope distinct from future evaluation, installation, and publication permissions.

## Applied changes

Use this section only after approval:

- Selected proposals and exact changed paths.
- Checks executed and results.
- Behavior evaluation completed or pending.
- Remaining proposals and uncertainty.
